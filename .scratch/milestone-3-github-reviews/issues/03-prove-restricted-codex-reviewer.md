# 03: Prove restricted Codex review preparation

Status: ready-for-agent
Resolved: no
Blocked by: None

**What to build:** Establish the same enforced, authenticated, pinned inspection contract for the supported native Codex integration, independently of the Claude result.

**Acceptance coverage:** Restricted-reviewer prerequisite for R3 and R10.

## Acceptance criteria

- [ ] Read the repository agent cost controls before any real-provider development or qualification launch. Use the required bounded cost profile and retain tool/model/version and usage evidence.
- [ ] Demonstrate real native inspection of pinned description, diff, relevant files and CI evidence using existing Codex authentication, returning structured findings or a valid complete no-findings result.
- [ ] Actively exercise arbitrary commands, builds/tests, coding-checkout writes and GitHub writes, including repository-guidance attempts. Verify enforced prevention rather than relying on prompt wording.
- [ ] Check the qualified execution configuration for inherited hooks/extensions, alternate tool paths and ordinary coding permissions that could bypass the inspection restriction.
- [ ] Exercise interruption, owned-child cleanup, malformed output and incomplete output while unrelated coding activity remains available.
- [ ] Retain executable evidence, credential assumptions, resource limits and the smallest reusable restricted Codex execution approach. Distinguish simulated checks from native qualification.
- [ ] An incompatible native integration returns for an explicit decision. Do not silently substitute unrestricted coding execution, change authentication expectations or claim both providers supported from one provider proof.

## Scope and handoff

Supply the qualified Codex execution approach to ticket 10. Claude and Codex proof work can proceed independently but shared lower-level changes must preserve the existing coding lifecycle. No publication is authorized.
