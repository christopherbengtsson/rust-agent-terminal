# Domain docs

This repo uses a single-context layout.

## Before exploring

Read root `GLOSSARY.md` and the ADRs under `docs/adr/` relevant to the
area being explored.

If domain documents are missing, proceed with the task. Domain modeling
creates or extends them when terminology or decisions are resolved.

## Vocabulary and decisions

Use the glossary's terms when naming domain concepts in specs, tickets,
code, tests, and proposals. Note meaningful terminology gaps for domain
modeling.

If a proposal contradicts an ADR, identify the decision and explain why
it should be reconsidered before overriding it.
